apx edits workspace files atomically. Submit one complete script as this tool's entire payload; rejection or cancellation changes nothing. Do not call it in parallel with other tools.

Commands: in PATH selects an existing UTF-8 file; new PATH creates and selects; mv DESTINATION moves the active file (select it first with in PATH); rm [PATH] removes PATH or the active file if PATH is omitted. sel LINE S:E (inclusive one-based code-point columns; one tab is one column), tsel FROM_LINE "TEXT" [N] (first N exact one-line matches), bsel "START" "END" (span through both unique anchors), rsel S:E (complete lines) select; type "TEXT" replaces or inserts; del, copy, cut, paste; commit.

Rules:
- Relative paths start at the host-supplied APX workspace base, not a task subdirectory or shell cwd; in Codex router sessions use repo-root paths with every nested component, or an exact absolute in-workspace path. Paths must stay inside the workspace root; `new` and `mv` create missing parent directories in the transaction and remove them on rollback; a final-component symbolic link rejects. An empty or unterminated new file rejects; end new-file text with `\n`.
- Coordinates are frozen immutable-baseline values from fresh nl -ba output; never adjust them for an earlier edit in the same script; inserted text is not selectable. commit advances the baseline and clears selections; after mv or rm, commit before reusing a changed path or selecting moved text.
- Minimize selector-plus-replacement output: tsel for fragments, bsel for uniquely anchored multiline regions (use distinctive full lines or signatures; never bare `}` or common setup lines; anchors are consumed; re-emit one that must remain); Omit leading whitespace unless it disambiguates, rsel for whole lines, sel for a later same-line match. Multiline text uses type <<PATCH with PATCH immediately after the final content line; an extra blank body line changes the output. Type text is literal and never inserts line breaks; use an escaped newline or a heredoc whenever a replacement crosses a physical line boundary. Never re-emit a whole file for a localized change (fewer than half of a file's lines change): keep untouched lines out of the replacement with tsel, bsel, or type; whole-file rsel is only for small files or true rewrites.
- Overlapping edits reject atomically; a baseline span accepts one edit. Combine related changes in one replacement or commit before selecting changed text again; correct from the repair coordinates a rejection supplies instead of rereading the file.
- After success, inspect the reported ranges and run the formatter or parser, relevant tests, and git diff --check.
